# 2026-10-30 修复总结

## 背景

Electron 侧 `tsc --noEmit -p tsconfig.node.json` 长期带 32 个类型错误，导致 `npm run build` 无法通过。本次清理将这些错误降到 0，并补齐了代码实际使用但未声明的类型依赖。

## 根因

1. **@types/node 版本漂移**：依赖树把 `@types/node` 提升到 26.6.5，该版本对 `net.Server` 的 `removeListener`/`off` 声明不完整，同时让 `https.get | http.get` 联合类型不可调用，产生主体错误。
2. **@ai-sdk 类型包未声明**：`electron/services/agentModelSafety.ts`、`agentPromptCache.ts`、`agentModelLedService.ts` 直接 `import type` 了 `@ai-sdk/provider` 与 `@ai-sdk/provider-utils`，但二者只是传递依赖。npm 扁平布局侥幸可用，pnpm 严格布局下报 TS2307。
3. **tsbuildinfo 陈旧缓存**：`tsconfig.node.tsbuildinfo` 记录了旧的模块解析路径，依赖调整后仍会复现旧错误，需要清理后重新生成。

## 改动

- `package.json` / `package-lock.json`
  - 新增 devDependency `@types/node: 24.12.0`，固定到与 Electron 43 兼容的版本线。
  - 新增 devDependency `@ai-sdk/provider: ^4.0.3`、`@ai-sdk/provider-utils: ^5.0.7`，采用区间而非精确版本：npm 锁解析到 4.0.3/5.0.7，pnpm 解析到 4.0.34/5.0.68，两个包管理器各自内部保持一致。
- `scripts/check-agent-sampling-options.cjs`
  - 类型剥离正则改为 `\r?\n`，兼容 Windows CRLF 检出，避免采样测试因换行符解析失败。
- 同批提交的 `wcdbCore.ts` DLL 回退与 `scripts/after-pack.cjs` 便携包内置 `wcdb_api.dll`，见提交 `394895e`。

## 遗留

- `native/wcdb-native/dist/` 被 `.gitignore` 的 `dist` 规则忽略，因此 DLL 改存到 `native/wcdb-native/prebuilt/` 并纳入版本库（`prebuilt/README.md` 记录来源与 sha256）；`afterPack` 默认读取该路径，CI（`CI=true` 或 `WCDB_DLL_REQUIRED=1`）缺 DLL 会直接失败，本地构建仍只告警。
- `native/wcdb-native/dist/` 仅作为本地 `cargo build --release` 的输出目录，重新构建后需把 DLL 复制到 `prebuilt/` 或设置 `WCDB_DLL_SOURCE`。
- `package.json` 中的 `pnpm.overrides` 在 pnpm 12 已不再读取，每次安装都会告警；若继续使用 pnpm，需要把 overrides 迁移到 `pnpm-workspace.yaml`。
- `pnpm-workspace.yaml` 与 `pnpm-lock.yaml` 都被 `.gitignore` 忽略，因此 `pnpm install --frozen-lockfile` 的通过结果只在本机可复现；README 记录的安装方式是 `npm install`，不受影响。
- `pnpm-workspace.yaml` 的 `allowBuilds` 未包含 `electron`，用 pnpm 全量重装后需要手动补齐 Electron 二进制。
